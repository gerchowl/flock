The S7-min types are generated from Rust into `web/client/src/gen/`. They define
contracts for the GUI and server work in #1746. The opt-in S7 endpoint serves
`fleet` subscriptions to read-scoped clients through its existing subscription
identity, delivery and heartbeat machinery. This stream does not execute commands.

`FleetAgentRow` contains `id`, `label`, `state`, optional `activity`, and required
`waiting_on_human: string[]`, plus optional `route`. State is the shared S4 `AgentState` object: axes, derived phase and sources.
Its per-field `or_unknown` deserializers follow ADR-0028 §3a, so an unknown
phase from a newer server becomes `unknown` while the other axes survive and
the fleet delta remains usable. The waiting IDs identify permission requests on `agent/<id>`;
there is no separate inbox stream in S7-min. Rows represent structured agents.
The server omits optional `activity` until the structured producer in
[#2243](https://github.com/gerchowl/flock/issues/2243) lands.
`waiting_on_human` contains only open, non-automatic harness permission request IDs.

### Fleet node and route metadata

`route?: Route` reuses mesh's existing `{node, name, next_hop, hops}` record
(ADR-0026; ADR-0038 §9). `node` is the SHA-256 hex digest of the owning node's
Ed25519 public key, as returned by mesh `NodeIdentity::node_id()`, not a host
label. `name` is its display name; `next_hop` is the first hop's node ID and
`hops` is the actual mesh path length. Route metadata is informational and grants no dialing or control authority.

The local structured-agent producer omits `route`. Legacy agent-only snapshots
remain readable; bound local rows also carry `node_id` and `project`. The generated GUI contract reserves it
for federated projection; remote fleet rows and remote command forwarding remain
out of scope until [#1380](https://github.com/gerchowl/flock/issues/1380).
The current GUI still presents a local flat fleet. Mesh protocol VERSION stays 5.

The `fleet` stream carries the closed `FleetDelta` union inside `ev`:

```json
{"type":"fleet.upsert","row":{"id":"example-agent","label":"Example","state":{"turn":"idle","background":"none","attention":{"needs_human":{"reason":"permission"}},"waiting":"none","lifecycle":"live","phase":"needs_human","source":{}},"waiting_on_human":["request-one"]}}
{"type":"fleet.remove","id":"example-agent"}
```

The N1a projection ([#2749](https://github.com/gerchowl/flock/issues/2749),
ADR-0043 NODE STATUS/N1) adds `fleet.node.upsert/remove` and
`fleet.project.upsert/remove` to the same union and durable cursor. Agent identity
is `(node_id, id)`, project identity is `(node_id, exact Record.cwd)`, and node
identity is the authenticated `node_id`. Project display basenames never define
identity. An agent with a non-UTF-8 working directory remains in the stream with
its node binding, but its optional `project` field is absent (project unavailable).
A content-free `fleet_project_unavailable` diagnostic is logged; no lossy project
identity is invented, and other rows and subsequent updates continue normally.
Unsafe JSON integers still refuse the whole observation and stop the publisher,
preserving its last durable cut until the source is corrected and the listener
restarted. Typed persistence also reads legacy bare agent rows;
unknown or invalid entries are skipped, logged and preserved raw.

The home row uses its actual server identity, an opaque `Node <node_id>` alias,
the build version, the existing machine-health sampler and `online: true`.
Its summary-request latency, last success and route remain `null`.

N1b1 ([#2762](https://github.com/gerchowl/flock/issues/2762)) projects App-owned
peer observations and the signed route table by authenticated NodeId. A retained
enrollment or a signed route supplies identity before a first summary; configured
names and SSH targets never do. Node and route display names use the same full
NodeId-derived alias. No private hostname or SSH error text reaches these rows.
A signed route proves the node identity, not the source of an arbitrary summary.
Direct facts require a matching independent enrollment pin. Relayed facts require
the immediate source captured from a validated poll or enrolled inbound edge
at ingestion to be that same owner. Rejected poll identities supply no relay
rows, and rebinding an alias cannot authenticate its old cached claims. Third-party
claims and carried snapshots cannot supply or freshen facts.
A healthy proven owner observation wins over failed paths. Among healthy
observations, the freshest wins, with a stable ordering for ties.
Direct latency is the last home-to-owner summary request in
milliseconds; relayed observations have `latency_ms: null`. Version and health
retain their owner identity; rebinding a peer clears the old owner's facts.
A failed first poll uses the independently enrolled owner identity and reports
its classified failure with unknown owner metrics. Latency provenance comes
from the direct observation source, never a matching configured name.

`last_ok` is Unix epoch milliseconds in the home clock domain, captured once per
successful observation. Each poll shares one observation instant with all of its
relayed rows. GUI requests and failed polls do not advance it.
Online classification uses monotonic age, including origin age plus local
residence for relayed observations. If no healthy path exists, unknown age,
absent/incompatible peer protocol, poll failure, missing live route and age
strictly greater than the effective `[gossip] stale_after_secs` threshold are
offline. The selected path's failure (or retained last-known cause while offline)
uses bounded
`pending`, `stale`, `route`, `peer_incompatible`, or classified SSH reasons.
A successful compatible observation with a live route clears `error`, including
when a direct link is failing. `link_diagnostics` independently retains current
direct-link failures as `{source_node_id, error}`: the source is the authenticated
serving home and the destination is this row's `node_id`. These classified,
content-free errors contain no SSH aliases, targets or stderr. They clear on
direct recovery or removal of the current binding/observation; the array is empty
when no current direct failure is known. Older stored rows default it to empty.
An unavailable home sample stays `health: null`; previous home health is not
reported as current. Thermal severity and component remain, but host-authored
thermal detail labels are omitted at read scope. A failed unpinned poll retains
last-known peer facts for existing offline diagnostics; it does not prove a
replacement identity or authorize those facts as a new owner observation.

Partial observations and route withdrawal retain known offline nodes and their
last-known health, version and display timestamp, including across store reopen.
Missing observations are not an authoritative node-removal or unenrollment
assertion. Local agent/project membership still uses complete registry cuts and
snapshot replacement still removes absent entities only at completion.

This slice publishes material status changes on the next App owner turn, without
GUI polling or a debounce. The independent expiry wakeup, local and provably
complete remote inventory counts, and the home unbound/unreached configured-peer
count are the authorised N1b2 slice
([#2761](https://github.com/gerchowl/flock/issues/2761)); counts remain `null` here.
Remote structured discovery does not carry project cwd or the full S4/permission
book, so this slice does not invent remote project or agent-state rows.

The generated
`FleetNodeRow` and `FleetProjectRow` declarations are authoritative. New entity
payloads are understood from client-wire version 1; older readers receive the
lossless `unknown` wrapper, including the original JSON and sender-scoped shape.
Mesh VERSION remains 5. The flat GUI adapter renders agent deltas and skips
node/project and unknown kinds without ending the subscription. Its cursor
advances across skipped payloads, including snapshot rows. Rendering nodes and
projects remains [G4 #1596](https://github.com/gerchowl/flock/issues/1596).

Decode fleet payloads as `FleetDelta`, rather than session `WireEvent`. Bootstrap
and recovery use ADR-0036 §5a's existing inline snapshot format: a `gap` announces
`snapshot_to`, complete row upserts follow, then `synced`. This is the snapshot's
collection of typed agent, node and project rows, not a new transport frame. On snapshot
completion, remove previously displayed rows absent from the fresh snapshot.
A `lagged` notification closes its subscription ID, like `subfail`. The server
sends nothing more on it; the client drops late frames and subscribes with a
fresh ID from the last applied cursor, without unsub. The new subscription gets
a gap/snapshot and its own synced barrier. Every subscription uses a fresh
ID on the connection, including recovery. After unsub, subfail or lagged, late frames
for the retired ID are silently dropped; frames for never-opened IDs are protocol
errors. Reusing a live or closed ID is refused with subfail code `sub_id_reused`. The `fleet-lite.jsonl` fixture pins
bootstrap, live updates/removal and recovery on the client.
`tests/fixtures/structured-wire/fleet-server.jsonl` separately drives the real
server owner and endpoint, including absent-row completion.

### Fleet-lite store recovery

An empty, unmarked lock with neither data record opens at zero. This includes an
empty legacy lock from the snapshot-only layout (#1974). Legacy locks were always
unmarked, even after positions had been published through `fleet.json`. That
layout's only high-water floor was `fleet.json`; if it is lost, there is no better
floor to recover. Opening at zero preserves the old behavior.

In the cursor-based layout, cursor durability precedes the initialization marker.
If an unmarked lock already has a matching cursor, opening fsyncs the cursor's
parent directory again before
marking the lock. This completes a previous initialization whose rename succeeded
but directory fsync failed. A directory-fsync error refuses opening and leaves
the lock unmarked for a later retry.
`fleet.lock` carries that marker, so deleting it together with `fleet.cursor`
while an older `fleet.json` survives reopens at that older head. The operator
must never delete the lock.

The stream owner persists `<data dir>/fleet.cursor` before replacing
`<data dir>/fleet.json`, under the existing exclusive `fleet.lock`.
It refreshes registry/S4/S6 observations before serving a cut. Checkpoint
allocation, publication of pending live deltas and registration of the new
subscriber are serialized off the app and heartbeat executors. Each checkpoint
is delivered only to its requesting subscription, through that cut's acknowledged
replay path. Concurrent mutations follow the immutable replay cut, after its
single synced barrier. Another reader's checkpoint cannot overflow the live ring.

The live ring holds sixteen frames within the existing 64 KiB message limit,
shared across cuts and carrying only live deltas. Row preflight reserves the
maximum JSON-escaped subscription-ID overhead within that limit, so a row near
the limit can lag even with a shorter actual ID. Each socket retains the existing eight-active-subscription
and 1024-lifetime-ID limits. A slow cut may lag even during initial replay;
resubscribe under a fresh ID from the applied cursor. Oversized rows also yield
lagged rather than truncated payloads; recovery cannot make an oversized row fit.
Captured checkpoints retain memory proportional to the fleet row count per
replay, under those cut limits. The latest coherent owner-turn materialization
may replace an unprocessed one;
use the agent journal for every intermediate event.

An unavailable permission-book observation leaves stored rows intact and fails
its readers instead of publishing an empty attention list. This includes a
preparing worker or one with unconfirmed cleanup: an absent Runtime book is
empty only when no worker exists or its producer is joined and its authority
released. A later coherent
observation can serve fresh readers. Storage failure stops the fleet owner,
logs the I/O kind and closes its readers. Repair the durable records as below
and restart the owner; no cursor is reset or write retried silently.

For a store named `fleet.json`, preserve `fleet.cursor` and `fleet.lock` during
recovery. A lost or corrupt snapshot opens with no rows at the cursor's preserved
high-water and exposes a typed `SnapshotMissing` or `SnapshotCorrupt` diagnostic.
Refresh the authoritative registry/S4/S6 provider before serving a recovery
snapshot. A failed snapshot write may reserve positions that were never published;
the recovery checkpoint covers those positions instead of reusing them.

Opening leaves damaged snapshot bytes untouched. Copy them before a refresh or
checkpoint replaces the file. If the cursor is missing after initialization or corrupt, or both recovery records
are missing from an initialized store, opening refuses a zero reset. With the owning
store closed, restore a trusted cursor backup or atomically replace its
`{"high_water":N}` record using temp-file fsync, rename and directory fsync.
Choose `N` at least as high as the surviving snapshot head and every cursor clients
have observed. If that floor is unknown, keep the store closed rather than guess.
A legacy valid snapshot with an unmarked lock seeds the cursor. A durable lock
marker then prevents a missing cursor from being mistaken for legacy migration
from an older snapshot. When both records are valid, the maximum high-water wins.

Skipped rows log their array index and `unsupported`, `invalid` or `duplicate`
reason without their contents. Unknown top-level row fields survive unchanged
rows and checkpoints, but are dropped when a fresh projection changes the row.

`agent.decide` takes `AgentDecide` arguments: `agent`, `request_id`, required `request_seq`, `decision`
(`allow_once`, `allow_always` or `deny`), and optional `message`. Only a
token-authenticated client principal can submit this command. The optional message
is normalized from CRLF to LF and trimmed, then limited to 2048 UTF-8 bytes
(`MAX_PERMISSION_DECISION_MESSAGE_BYTES`). The `prompt_control_bytes` rules
permit newlines and tabs and refuse other controls. Invalid messages return
`invalid_params` before any reservation, grant, audit or harness input. Empty
and absent messages are allowed. The ack uses the
same envelope as `agent.send`, echoes `cmd_id`, and on success returns
`AgentDecideResult`, echoing the applied request ID and decision:

```json
{"t":"ack","cmd_id":"decision-one","ok":true,"result":{"request_id":"request-one","decision":"allow_once"}}
```

Failures use `ok: false` and the existing `WireError` envelope without `result`.
`AgentDecideErrorCode` names `permission_request_unknown`,
`permission_request_closed`, `not_authorized` and `invalid_params`, with retry class `never`.
These names are contracts for S6 (#1429) to register before serving them; this
slice adds no API error registrations or authorization behavior.

Live structured runtimes keep at most 16 open/in-flight requests
(`MAX_OPEN_PERMISSION_REQUESTS`). The harness blocks per request, so more than a
few concurrent prompts is pathological; 16 leaves headroom for parallel tool
calls. An extra valid request receives a `permission_request_limit` deny (retry
`never`), a structured warning and a durable closed audit with no matching open
audit. The other requests and the session remain live.

Every open request carries a flk-issued `request_seq: u64` in its audit, trusted
stdout envelope and S4 snapshot. It increases strictly within the session,
including across runtime resumes. S7 slice 5 must carry both `request_id` and
`request_seq` from that display to `agent.decide`; an ID alone cannot authorize
an answer. Like stream cursors, generated TypeScript represents this JSON number
as `number`, exact below 2^53. Clients must preserve the exact value.

The most recent 1024 closed `(request_id, request_seq)` handles are retained in
FIFO closure order. A decision for a retained closed pair returns
`permission_request_closed`; an evicted or never-seen pair returns
`permission_request_unknown`. A reused harness ID receives a new sequence:
a delayed decision for its old handle cannot approve the new request or install
an `allow_always` grant. Session grants remain exact matches for this live runtime.

## Permission lifecycle records

`flk_permission_request` is a known agent-stream event, exported as the generated
`PermissionRecord` type. Its `state` is `open` or `closed`; there is no `decided`
state. Both carry `request_id` and the flk-issued `request_seq`. Only `open`
carries `request: ToolRequest`, from which the client renders the tool summary.
A close carries `decision`, nullable `message`, `principal` and `source`, or a
closed reason enum. Capacity refusals use `permission_request_limit` and may
have no preceding open. Other reasons include `ended`, `cancelled`, `result`,
`interrupted`, `permission_request_too_large`, and `session_ended` (a prior
runtime left an unmatched open). Existing closed JSON is preserved apart from `request_seq`.

The `permission-decision` fixture shows open, `agent.decide` acknowledgement,
then closed. The ack acknowledges admission; remove the card when the durable
closed event arrives. Future or incompatible record shapes use the existing
unknown-event wrapper, preserving their original payload.

On session start or resume, the owner closes unmatched permission records with
`session_ended` before processing new control requests, including interrupted
automatic approvals. The closes use normal durable audit ordering; an I/O
failure stops the owner. Repeated starts add no duplicate close. Old permission
slots and exact grants are not restored. Legacy opens without `request_seq`
use their durable stream position for the recovery close; an old close without
a handle matches by ID. Unknown records remain untouched, and invalid permission
headers are logged and preserved rather than failing the entire recovery scan.


## Agent lifecycle commands

JSON wire version 2 accepts `agent.start`, `agent.restart`, and `agent.stop`.
Their arguments reuse the socket API's `AgentStartParams`, `AgentRestartParams`,
and `AgentTarget`. All three require `operate`; a send-only token receives
`not_authorized` before argument or target lookup. The generated
`AgentLifecycleCommand` TypeScript type lists the verbs and argument types.

Lifecycle arguments may additionally carry `node_id`. Omit it for this server,
or supply this server's pinned NodeId. Another node receives
`unsupported_for_agent` before any local dispatch. A target agent ID known
through the remote fleet directory receives the same refusal, even without
`node_id`. Remote lifecycle forwarding
remains gated by ADR-0043.

An authenticated replay of the same principal, command ID, verb and arguments
returns the first lifecycle ack while that entry remains in the owner's bounded
1,024-command retention set. Reusing a retained ID with different arguments or
verb refuses `invalid_params`. Revocation and scope checks precede replay.
An uncertain retry with `resume_only: true` and no retained result refuses
`session_unconfirmed`; it never launches again. Retention is in memory and
ends on server restart or eviction.

`agent.start` permits fresh launches through the existing server-side launch
gates, including `structured_needs_agent_user`. It cannot resume a structured
record: that receives `operator_only`.

An operator app-session token with `operate` may stop a structured agent or
restart a stopped structured agent on its home node. Restart resumes the same
agent and session ID through the socket structured-resume funnel, including
run-as, recovery and spawn admission. An active worker refuses replacement with
`session_busy`; uncertain recovery state refuses `structured_recovery_required`.
`continue_with` is unsupported for structured
restart; `when` must be `after_turn` and `reason` must be nonempty plain text
of at most 1,024 bytes. Stop requests asynchronous cleanup; inspect `agent.list`
or `agent.get` for confirmed `offline` state. Owner-side stop/restart decisions,
including refusals and replays, log the requested `target`, resolved `agent_id`
and `session_id` when known, authenticated `principal`, per-mint `app:<nonce>`
credential identity, and outcome. Unresolved identities use empty ID fields.
Generic ingress refusals (including version, command-ID and capacity checks)
and queue-full refusals before owner dispatch retain their pre-existing audit gap.

The GUI's agent view and command palette offer **Stop agent** with a confirmation
and **Restart agent** when the agent is offline. Restart resumes the existing
session; stop it first if it is still running. A stop acknowledgement says cleanup
was requested; the view follows the server's state until it reports offline.
These actions require the operator app on the home node. Browser file credentials
receive a plain-language refusal with the server code available under **Details**.

File credentials retain `operator_only` for structured stop and
`runtime_unsupported` for structured restart, even with `operate`. Tokens
without `operate` receive `not_authorized`. Agent callers and mesh relays gain
no resume authority. The socket API still refuses PTY `agent.stop` with
`runtime_unsupported`; the wire preserves that behavior.
[ADR-0036 §1a](https://github.com/gerchowl/flock/blob/dev/docs/adr/0036-structured-agent-sessions.md#1a-identity-and-the-operator-boundary-for-structured-agents)
defines the app-session authority boundary. ADR-0052 slice 17 will add profile
admission at the shared socket/wire entry for profile-bound execution.

## New agent picker

In the live GUI, **New agent** opens a sheet from the toolbar or command
palette. Enter a name, choose a node and an absolute working directory, then
select **Start agent**. Reported project paths are offered as choices, with the
first selected by default; you can also type another path. The home node is
selected by default. Runtime is **Structured** and harness is **Claude Code**, the currently supported adapter.
An empty or relative working directory keeps **Start agent** disabled. The
server checks that the directory exists on the chosen node.

The picker sends `agent.start` through the existing command outbox and shows
the server’s acknowledgment. An unresolved start stays disabled to prevent a
second launch. A non-home selection shows a plain-language refusal with the
server code available under **Details**. Server admission and operator authority
gates still apply.

## Unsupported command verbs

After authentication, an otherwise valid, bounded `cmd` frame with an unknown
`verb` is refused for that command with
`server_version_gap`, following ADR-0036 §5 protocol gating. The existing
registered code has one retry class, `after_handoff`, and exit 78. The ack echoes
`cmd_id`, sets `ok: false`, and carries the ADR-0029 error envelope in `error`;
there is no `result` or top-level `code` field:

```json
{"t":"ack","cmd_id":"unsupported-one","ok":false,"error":{"code":"server_version_gap","message":"command refused: server_version_gap","exit":78,"retry":"after_handoff"}}
```

The refusal does not close the connection or submit the unsupported command.
The next supported command or subscription can use the same socket. Repeating
an unknown verb on the same server does not make it supported; use a compatible
server/version before retrying. This command-level refusal does not change the
existing protocol-close rules for malformed frames or invalid session traffic.

### Refusal audit events

Every authenticated wire request refusal produces a best-effort `wire_refused`
event through the server event hub and socket event APIs. This includes command
ingress, owner admission (scope, revocation and capacity), argument validation,
dispatch, replay/resume refusals, cached failed outcomes and failed input
receipts. The owner records command failures before sending the reply, including
when the reply's reader has disconnected. Full or closed enqueue lanes are
recorded at enqueue. Existing responses, uncertainty and retry classes stay
unchanged; an audited error does not prove an uncertain input had no effect.

Subscription auditing covers identity/length/capacity rejection, reused IDs,
read authorization, unknown or invalid streams, cursor/replay failures and
storage unavailability. Authenticated JSON/framing/binary protocol refusals and
ignored invalid or excess JSON probes are also recorded. Idempotent unsubscribe,
normal disconnect and idle liveness expiry are not refused requests.

The event data has `type: "wire_refused"`, verified `principal`, public
`token_id` (file-token name or per-mint app-session label), normalized `verb`,
parsed `target` (first 256 Unicode characters), typed `reason`, and
`suppressed: 0`. Targets come from `args.target`, `args.agent` or the subscription
`stream`. Reasons use registered command error codes or the closed subscription
refusal codes. Malformed frames use `invalid_params`; transport/framing read
errors use `internal_error`. Known command verbs keep
their names; unknown commands all normalize to `unknown`. Control categories
are `sub`, `unsub`, `ping`, `pong`, and `protocol` (when no request verb can be
parsed). Bearer secrets, command bodies, nonces and raw unknown verbs are never
recorded.

One server-wide monotonic 60-second window permits eight individual events per
`(principal, verb, reason)`, with at most 64 resident keys and 128 individual
events globally. No key is evicted or given a new budget within that window.
Excess refusals for a resident key accumulate into one summary with the same
principal, verb and reason, null target/token ID, and the exact `suppressed`
count. Once either the key capacity or global event budget prevents admission,
refusals join an aggregate overflow count. At window closure there is at most
one aggregate summary, with null principal/token ID/verb/target/reason and the
exact total suppressed by overflow. Per-key counts apply only while resident
and within the global budget. Shared operator principals share budgets across
tokens; summaries do not claim attribution to one of those tokens.

Summaries use the same event kind and are outside the individual-event budget:
at most 65 summaries and 128 individual events per window. The owner tick or
next refusal closes an expired window, including idle keys. Graceful shutdown
drains connections and flushes the current partial window's exact suppression
counts; repeated shutdown does not repeat summaries. A crash or abrupt owner
drop can lose pending counts. Restart and handoff start fresh budgets; there is
no global lifetime or cross-server rate guarantee.

The limiter decides and constructs events under its mutex, then releases that
mutex before `EventHub::push`. Journal I/O can still block a publishing caller,
but never holds the limiter lock across I/O or prevents concurrent refusal
budget decisions. Publication is best-effort, rather than a required-audit
mutation fence: failure can degrade to memory-only events and never changes a
request's outcome. Existing required mutation audits retain their own fences.
Pre-authentication failures remain unaudited: they lack a verified principal
and must not provide an unauthenticated journal-amplification path.
