---
title: Install Flock
description: Install, update, and verify Flock on Linux and macOS.
---

Flock ships as a single binary for Linux and macOS.

## Install

Run the installer:

```bash
curl -fsSL https://flock.dev/install.sh | sh
```

The installer downloads the right release binary for your platform and places it on your PATH.

## Install with Homebrew

If you already use Homebrew:

```bash
brew install flock
```

## Install with mise

If you already use mise:

```bash
mise use -g flock
```

## Verify

Start Flock:

```bash
flk
```

If your shell cannot find `flk`, restart the terminal or check that the install directory is on your PATH.

## Update

Flock checks for new releases and notifies you in the app. You can update manually:

```bash
flk update
```

`flk update` is for installs managed by Flock's own installer. Homebrew, mise, and Nix installs are updated through those package managers instead.

Flock uses the stable update channel by default. To opt into preview builds from `main`, set the channel:

```bash
flk channel set preview
```

Switch back to stable the same way:

```bash
flk channel set stable
```

For direct installs, changing channels also checks that channel and installs its latest binary. If that update fails, run `flk update` to retry from the configured channel.

Preview builds are GitHub prereleases published from the current development branch. They are useful when you want fixes before the next stable release, but they can regress. Homebrew, mise, and Nix installs do not use the preview channel.

By default, `flk update` installs the new binary and leaves compatible running sessions alone. If an update changes Flock's client/server protocol, Flock asks whether to stop the old server after installing. Stop the old server to use the new version. Stopping exits pane processes. For the default session, run `flk server stop`, then run `flk` again. For a named session, run `flk session stop <name>`, then run `flk session attach <name>` again.

To opt into experimental live server handoff for supported running sessions, run:

```bash
flk update --handoff
```

Live handoff does not apply to Homebrew, mise, or Nix package-manager updates. For those installs, update with the package manager, then restart that Flock session when you are ready to use the new server. If a running session still uses the old server, stop it with `flk server stop` or `flk session stop <name>`, then run Flock again.

## Install with Nix

If you already use Nix, Flock provides a flake that builds Flock from source:

```bash
nix run github:gerchowl/flock/v1.x.y
nix build github:gerchowl/flock/v1.x.y
nix profile install github:gerchowl/flock/v1.x.y
```

Replace `v1.x.y` with the latest release tag. You can omit the tag to track `main`, but release tags are recommended for normal installs.

The flake also exposes a development shell:

```bash
nix develop github:gerchowl/flock
```

The devShell wraps sccache so its daemon uses `$HOME/.cache/sccache/tmp` and
`$HOME/.cache/sccache/flock.sock`, shared across worktrees for the same user.
The artifact cache is `$HOME/.cache/sccache`. This implements the stable-directory
and isolated-server design accepted in [issue #1325](https://github.com/gerchowl/flock/issues/1325).
[sccache 0.15 supports a Unix socket or explicit port](https://github.com/mozilla/sccache/blob/v0.15.0/README.md#usage),
while [`SCCACHE_DIR` only selects artifact storage](https://github.com/mozilla/sccache/blob/v0.15.0/docs/Configuration.md#disk-local).
It has no server-only temporary-directory setting, so the wrapper sets `TMPDIR`
for each sccache invocation, including compiler subprocesses. Other devShell
commands retain their own `TMPDIR`. A persistent directory avoids scratch-directory
cleanup breaking later builds, at the cost of keeping daemon temporary files in
the cache tree. The separate socket avoids reusing a daemon already started on
the default port 4226 with a disposable directory.

Set `SCCACHE_DIR` to override the cache root and its `tmp` subdirectory. Explicit
`SCCACHE_SERVER_UDS` or `SCCACHE_SERVER_PORT` overrides the default socket, so you
must ensure that endpoint's daemon was also started through the wrapper. Keep
these paths absolute, persistent, and writable. Unix socket path limits apply (roughly 104
bytes on macOS), so use a shorter persistent cache root or an explicit private
port for a long home path. Existing platform-default artifact caches are not
moved automatically, so the first build may repopulate the new root. Failure to create the temp directory prints its path
and fails the build. Do not delete the cache tree while its daemon is running.
`RUSTC_WRAPPER=""` still disables Rust caching, and custom wrappers remain intact.
Run `nix develop --command just test-sccache` to check deleted startup directories,
server restarts, and rebuild cache hits using isolated servers.

Update through the same Nix workflow you used to install Flock. For a profile install, list your profile entries and upgrade the Flock entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Flock is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update flock
```

## Download manually

You can also download a binary from [GitHub releases](https://github.com/gerchowl/flock/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `flock-linux-x86_64` |
| Linux aarch64 | `flock-linux-aarch64` |
| macOS Intel | `flock-macos-x86_64` |
| macOS Apple silicon | `flock-macos-aarch64` |

Make it executable and move it somewhere on your PATH.

```bash
chmod +x flock-linux-x86_64
mv flock-linux-x86_64 ~/.local/bin/flock
```

## Requirements

Flock supports Linux and macOS. Native Windows support is not available yet; use Flock inside WSL for now.
