---
title: How to work with Flock
description: Run Flock locally, inside SSH, or through remote attach.
---

Run Flock where the work lives. Attach from wherever you are.

Flock is a background session server plus one or more terminal clients. Panes keep running in the server. Clients attach, detach, and render the session.

## Local work

Start Flock from the project directory:

```bash
flk
```

Flock starts or attaches to your local background session automatically. You do not manage sockets. Run shells, servers, tests, and agents normally inside panes.

Detach the client with `ctrl+b q`. Your panes keep running.

Flock selects the first terminal on stdout, stdin, or `/dev/tty`, so a stdio
PTY works even without a controlling tty. At startup it waits up to two seconds
for nonzero geometry (including a PTY created at 0×0). If geometry never becomes
valid, startup fails visibly with `timeout`; with no tty at all it fails with
`terminal_unavailable`. Sizing happens before connecting, so an unsized terminal
occupies no server handshake slot. Quitting during the wait exits cleanly.
Local geometry failures are final even during a live handoff; they do not consume
its reconnect window. Neither path sends an invented 80×24 size.

Once a terminal is selected, `EIO`, `ENXIO`, or `ENOTTY` on that tty detaches the
client. Other query errors retain the last known geometry and send no resize.
The structured debug event `client.geometry_query_failed` records failure state
transitions, rather than every poll. A confirmed tty-loss exit is final and does
not start a redial loop.

Reattach later:

```bash
flk
```

If you want to end the session and stop its panes, stop the server:

```bash
flk server stop
```

## Remote work through normal SSH

SSH to the machine that has the code and credentials, then run Flock there:

```bash
ssh you@server
flk
```

This works like a terminal multiplexer. Your shell is remote. The Flock server is remote. The agents and panes run on the remote machine. Detach with `ctrl+b q`, disconnect, then SSH back and run `flk` again.

Use this path when you already live inside an SSH shell, when you are on a phone or tablet SSH client, or when you want the simplest possible setup.

## Work from your phone

You do not need a Flock mobile app or a web dashboard. Install any SSH client on your phone, connect to the machine where your agents run, and start Flock there:

```bash
ssh you@server
flk
```

The same persistent Flock session opens in your phone terminal. The TUI adapts to narrow screens, so you can inspect agents, switch workspaces, and check panes without leaving SSH.

On iPhone, apps like [moshi](https://getmoshi.app/) work well.

## Remote work from your local terminal

Attach through SSH without opening a shell first:

```bash
flk --remote workbox
flk --remote ssh://you@server:2222
```

Your local Flock acts as a thin client. It connects over SSH, starts or attaches to the remote Flock server, and streams the UI back to your local terminal.

Use this path when you want the remote session to feel local. The client runs on your machine, so local desktop features such as image clipboard paste can be bridged to the remote server. If you SSH first and run `flk` on the server, Flock runs entirely on that server and cannot read your local desktop clipboard.

For repeat targets, put the host in your SSH config:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

Then attach with:

```bash
flk --remote workbox
```

## Which path to use

Use `flk` for local work. Use `ssh you@server` then `flk` when you want Flock to behave like tmux on that remote shell or when you are using a phone SSH client. Use `flk --remote <host>` when you want a local thin client for a remote session, including local clipboard image paste bridging.

For remote bootstrap details, named remote sessions, custom binaries, direct terminal attach, and `--no-session`, see [Persistence and remote access](/docs/persistence-remote/).
