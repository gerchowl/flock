- `flk worktree kill`, `worktree list --scan`, the TUI kill dialog, the kill-all sweep and the scheduled reap no longer call a branch merged because some other remote feature branch contains it (#1278). A branch with an open PR that its builder had also merged into a second, unmerged feature branch read `merged`, with evidence `contained in origin/<feature>`, and a kill would have deleted the checkout and branch of a PR under review. Merge evidence is now only a merged PR, the landing branches (the detected default, `dev`, `main`, `master`, `[worktrees] integration_branches`), the base branch of the branch's own PR, squash or rebase content already in one of those, and a never-pushed branch with no commits of its own beyond another local branch. The PR is asked first, pinned to the `origin` repo and then through gh's own resolution. An open PR gives the verdict `open_pr`; a `gh` that cannot answer for a repo with a github.com remote (rate limit, offline, logged out, missing) gives `unknown`, never "no PR". For both, `--dry-run` reports `would_delete_branch: false` (with `open_pr: true` or `merge_unknown: true`), a real kill (including `delegate reap`) is refused with `worktree_open_pr` or `worktree_merge_unknown`, exit 10, before anything moves, and `--force` does not clear it; `--keep-branch` removes the checkout alone. The kill-all sweep and the scheduled reap skip such checkouts entirely, forced or not, and so does a sweep row whose gate timed out; the TUI kill dialog keeps such a branch even when forced. Known limits: a branch merged only into a feature branch outside the landing set needs `--keep-branch`, a manual `git branch -D`, or that branch in `integration_branches`; on a github.com repo, cleanup waits while `gh` is unavailable; a GitHub Enterprise remote is not recognised as GitHub.
