- `flk worktree kill` and `worktree list --scan` no longer call a branch merged because some other remote feature branch contains it (#1278). A branch with an open PR that its builder had also merged into a second, unmerged feature branch read `merged`, with evidence `contained in origin/<feature>`, and a kill would have deleted the checkout and branch of a PR under review. Merge evidence is now only a merged PR, the landing branches (the detected default, `dev`, `main`, `master`, `[worktrees] integration_branches`), the base branch of the branch's own PR, squash or rebase content already in one of those, and a never-pushed branch with no commits of its own beyond another local branch. An open PR on the branch is checked first and wins: `--scan` reports `open_pr`, `--dry-run` reports `open_pr: true` and `would_delete_branch: false`, and a real kill (including `delegate reap`) is refused with `worktree_open_pr`, exit 10, before anything moves; `--force` does not clear it, `--keep-branch` removes the checkout alone. The TUI kill dialog keeps such a branch even when forced. Known limit: a branch merged into a feature branch that is not in the landing set now needs `--keep-branch` or a manual `git branch -D`, or that branch listed in `integration_branches`.
