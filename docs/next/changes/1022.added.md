- The `state` object on `agent.get` / `agent.list` fills its `background` axis (#1022): `"none"`, `{"running": {"count": N}}` or `"unknown"`, with `source.background` naming where the count came from. Claude's comes from its screen (the footer's `N shells` counter, or the `still running` suffix of the turn's `done` line), so a settled Claude turn now reads `phase: finished`, or `finished_with_background` while a `run_in_background` shell or monitor is still alive. Codex and opencode report `process_tree`: once the turn is idle, the pane's process tree is read, and a shell the harness spawned, a command on its own terminal (a Codex background terminal) or a `cmd &` left in the pane's session counts as one job; MCP servers and other helpers the harness keeps do not. Other harnesses stay `unknown`. An older client reads the new `running` shape as `unknown` and keeps the other axes.
