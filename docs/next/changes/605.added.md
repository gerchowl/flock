- Claude Code agents started in a linked git worktree no longer stop on Claude's folder-trust dialog when the repository the worktree came from is already trusted. Before `flk agent start`, `flk delegate start` (`--worktree`, or `--cwd` into a linked worktree), `agent.spawn` or a fork execs `claude`, flock writes `projects[<worktree>].hasTrustDialogAccepted = true` into the `.claude.json` of the profile the child runs under (`$CLAUDE_CONFIG_DIR/.claude.json`, else `~/.claude.json`). It never widens trust: the entry is written only when the same directory in the main checkout is trusted by Claude's own lookup (which stops at the git root), and a directory that is not inside a linked worktree, such as `$HOME`, is never touched. The edit splices only the bytes it adds, keeps the file's mode, re-reads the file just before an atomic replace and retries once if Claude rewrote it meanwhile, and skips a symlinked or read-only config. Opt out with `[worktrees] pretrust_claude = false` (#605)
