- Channel token issuing (#1170, follow-up to #1037). Replacing an untrusted token file now renames the new token over it, so the name is never briefly missing. Temp files are named after the writing process (`.<pid>-<random>.tmp`), and the sweep at each issue removes only those whose process has exited, so two servers issuing during a live handoff no longer delete each other's temp file and log a spurious `channel.token.issue_failed`. The socket API reference now lists `token_unavailable` among the `channel.hello.refused` log reasons.
