- Owner bindings on the server, the first slice of the resident repo owner (#1196, ADR-0035 §1). Four new socket methods: `owner.bind` binds a repo (by GitHub slug) to its owner on the serving node, which becomes the owner's home node, with a checkout, a harness (`claude`, `codex` or `opencode`), an optional model and a profile ladder; the server mints the owner's `agent_id`, and binding the repo again keeps it. `owner.unbind` ends a binding, and `owner.list` and `owner.show` read them; the MCP tool `flock_owner_show` reads one. Binding and unbinding are operator verbs: a caller in an agent's pane, or a request relayed from a mesh peer, is refused with `operator_only` and nothing changes. Two new durable event kinds, `owner_bound` and `owner_unbound`, record the binding. It is folded once per server start and re-issued on start and after every log rotation, so it survives both. Protocol 30: `owner.bind` and `owner.unbind` count as state-changing for the skew gate. Servers from 2.0.0 skip the new kinds; a 1.x server quarantines a log that holds them. The `flk owner` verbs (#1231) and the layer-one report (#1232) follow.
