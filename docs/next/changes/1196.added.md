- Owner bindings, the first slice of the resident repo owner (#1196, ADR-0035 §1). `flk owner bind <owner/repo> --checkout PATH --harness <claude|codex|opencode> [--model M] [--profile P]...` binds a repo to its owner on the node that runs it, which becomes the owner's home node; the server mints the owner's `agent_id`, and binding the repo again keeps it. `flk owner unbind`, `list` and `show` end and read bindings, and the MCP tool `flock_owner_show` reads one. Binding and unbinding are operator verbs: from an agent's pane they exit 13 (`operator_only`) and change nothing. After a bind, the reply's `layer_one` reports which ADR-0035 §6.3 safeguards are in place for the repo, read from GitHub and never changed. Two new durable event kinds, `owner_bound` and `owner_unbound`, record the binding; it is folded once per server start and re-issued on start and after every log rotation, so it survives both. Protocol 30: `owner.bind` and `owner.unbind` exit 78 against an older server. Servers from 2.0.0 skip the new kinds; a 1.x server quarantines a log that holds them. Exit code 13 gains a second registered meaning, `OPERATOR_ONLY`.
