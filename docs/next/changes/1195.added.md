- Owner policy from `.flk.toml`, adopted by the operator (#1195, ADR-0035 §3 and §6.2, slice O0). flk reads the `[owner]` section of `.flk.toml` as committed on the repo's default branch (`origin/<default>`), through the git common dir, so a worktree's edit or a PR branch is never read (ADR-0004 decisions 4–5). This release reads `[owner.wake]` and `[owner.standup]` and lists any other `[owner]` key as ignored. The policy version is the file's blob id. A merged change does not apply until the operator runs `flk owner policy adopt <version>` (socket `owner.policy.adopt`). Until then `flk owner policy show` (`owner.policy.show`) reports it as `pending` and the previously adopted version applies. Adoptions are recorded as the durable `owner_policy_adopted` event and re-issued on every start and log rotation. `adopt` is refused with `operator_only` for an agent pane, a mesh relay or an unattested caller. That refusal is cooperative until agents run as their own Unix user (#1208).
- The error-code registry maps `operator_only` to exit 13 (`POLICY_REFUSED`, ADR-0029 §2's "refused by policy or scope"), so MCP's `data.exit` for a refused `peers.enroll_reset` is now 13 instead of 1. A guarded CLI verb that ends in an error now exits with the code the registry assigns instead of 1, which also makes `server_version_gap` exit 78 there.
