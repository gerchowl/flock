- A live handoff no longer leaves idle agent panes blank. Agent panes replay no history into the importing server, and an idle TUI does not redraw by itself, so every pane outside the active tab came back with an empty screen until a client attached, and the screen-gated idle wake held `needs_reply` mail for idle agents indefinitely on an unattended server. The importer now sends every imported pane a resize nudge as soon as it owns the panes, with or without a client (#977)
- `msg status` no longer reports `delivered` for mail that is still unread in an inbox on the same server. It reports `queued`, with detail `waiting in a local inbox, not yet read`, until `msg read` takes it, which matches `msg list` and the older local path. `delivered` still means imported into another node's inbox, and receipts sent to another node are unchanged (#977)
- `agent result` and `agent history` keep reading a Claude or OpenCode pane after a live handoff. The handoff manifest now records which panes' sessions a hook had confirmed, and the importer keeps that confirmation, because the same process holds the same PTY. An older sender omits the field, and its sessions arrive unconfirmed as before. A session flock restored but no hook has confirmed since is refused with the new code `session_unconfirmed` and a retry hint, not with `unsupported_for_agent`, which claimed flock could not read Claude at all. A Claude transcript is now also found under the `CLAUDE_CONFIG_DIR` profile its session was recorded with, not only under `~/.claude` (#977)
