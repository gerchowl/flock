- `events.subscribe` now starts at the moment of subscribing instead of replaying the events the server still held. Pass `after: <seq>` to start from a cursor; a subscriber the server's retention has left behind gets a `lagged { skipped_to }` line instead of losing events silently, and a cursor past the newest event is refused with `cursor_ahead` (ADR-0028 §3) (#1030)
- `flk delegate wait` and `flk agent wait --status settled` wait on `events.read` against a server at protocol 28 or later: the server holds one request until an event about the agent lands or the settle window is due, instead of the client polling the agent and its pane every 200 ms. Against an older server they keep polling. Exit codes are unchanged (#1030)
