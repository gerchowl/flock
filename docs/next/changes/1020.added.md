- The PR poller now records CI and PR outcomes as durable events (#1020, ADR-0028 §2). The same batched GraphQL request that drives the sidebar badge also reads each PR's head commit and its check results, so no request is added. Three kinds land in the event log: `pr.ci_completed { repo, branch, pr, head_sha, conclusion, failed_checks }`, once per head SHA when every check on it has concluded; `pr.merged` and `pr.closed`, once per PR. Each fact is emitted once across repeated polls and server restarts, because the poller seeds its record from the log on the first round after a start. A commit with no checks never produces `pr.ci_completed`. The event-log reader now skips a line whose kind it does not know instead of quarantining the whole active log, and keeps that line's sequence number spent, so a downgrade or the old side of a live handoff keeps its history (ADR-0028 §3a).
