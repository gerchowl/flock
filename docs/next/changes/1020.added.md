- The PR poller now records CI and PR outcomes as durable events (#1020, ADR-0028 §2). The same batched GraphQL request that drives the sidebar badge also reads each PR's head commit and its check results, so no request is added. Three kinds land in the event log: `pr.ci_completed { repo, branch, pr, head_sha, conclusion, failed_checks }`, once per head SHA when every check on it has concluded; `pr.merged` and `pr.closed`, once per PR. The first conclusion on a SHA wins, so a CI re-run on the same SHA is not announced again. A head with more checks than one page (100) holds does not conclude. Each fact is emitted once across repeated polls and server restarts, because the poller seeds its record from the log, read off the main loop, on the first round after a start. PRs that round already sees merged or closed are treated as history and not announced. A commit with no checks never produces `pr.ci_completed`. These kinds need a reader that skips unknown kinds (#1058) in the release before this one, so a downgrade keeps its log.
