- Live handoff no longer times out forever on a pane with a healthy terminal (#1011). An empty input write (from an inbox wake, paste or injection) used to sit at the head of the pane's write queue and be retried forever, because writing zero bytes "succeeds" by writing nothing. Empty writes are now never queued and are skipped if one is already queued. A write of a non-empty buffer that keeps accepting zero bytes is retried a bounded number of times, then the pane's writer is given up on with one log line. This also ends the flood of `PTY actor write returned zero bytes` warnings in the server log (#997).
- A live handoff that still cannot drain a pane names it (#981): the error lists each stuck pane as `wX:pN` with its pending bytes, pid and title instead of an anonymous timeout. `flk server live-handoff --skip-undrained` hands off anyway, drops those panes' pending input and prints what it dropped per pane. A server older than this release still sends the bare error, so the CLI prints how to find and close the stuck panes on it.
