- `flk worktree create --base` and the TUI's new-worktree dialog refresh the base from its remote the same way `delegate start --base` does, through one shared resolver, so a local `dev` nobody pulled no longer decides what a new worktree starts from (#938). `worktree create` prints the ref and commit it used. A raw socket `worktree.create` still uses its `base` as written: the server loop never waits on the network.
- A tag base (`--base v1.0`) is no longer fetched as if it were a branch; it is used as written and its commit is reported. A branch the remote lacks is detected by `git ls-remote --exit-code` instead of git's English error text, and an unreachable remote is reported after one bounded wait.
- `flk delegate start --json` prints a `start_failed` outcome carrying the agent pane's last lines as `data.pane_tail` (and `ready_timeout` carries them too), and so does a start whose brief submission could not be confirmed. `--keep-on-failure` now also keeps the workspace and checkout when the server refuses to start the agent; `delegate status` reports such a delegate as `not_started`, `send` refuses it as gone, and `reap` removes it.
