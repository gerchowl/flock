- New socket method `events.read { after, kinds, subjects, limit, wait_ms }` reads the durable event log from a cursor the caller holds (ADR-0028 §3). It serves from the in-memory ring and falls back to the rotated log files on disk, so a reader that was away for hours misses nothing the log still holds. When the cursor is older than what is retained, the reply starts with `gap { from, to }` instead of skipping silently. `wait_ms` (at most 540 s) holds the request on the server until a matching event lands. Delivery is at-least-once: dedupe on `seq` and resume from `next_after`. Only durable kinds are served; asking for `pane_output_changed` or a mesh kind is refused. The socket protocol rises to 28, so a client asking an older server gets `server_version_gap` (exit 78) (#1028)
