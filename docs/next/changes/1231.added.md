- `flk owner bind|unbind|list|show`, the operator's verbs over the owner bindings of #1196 (ADR-0035 §1, #1231). `bind` takes the repo's GitHub slug, `--checkout`, `--harness claude|codex|opencode`, an optional `--model` and a repeatable `--profile`; each verb prints the server's reply, and under `--json` an error is the ADR-0029 envelope. `bind` and `unbind` run from an agent's pane, a mesh relay or an unattested caller are refused with `operator_only` and exit 13 (cooperative only until agents run as their own Unix user, #1208). `unbind` and `show` of an unbound repo exit 4. The exit-code registry now maps `operator_only` to 13 on every verb, so `flk peers enroll --reset` refused from an agent pane exits 13 instead of 1, and every verb, send-like and guarded ones included, now exits the registered code of its error, as MCP's `data.exit` already reports (#1241): `server_version_gap` exits 78 instead of 1, `questions_widening_refused` and `operator_only` 13 instead of 1.
