- A server restart no longer loses agents (#1010). A hibernated agent's resume plan is saved in the session snapshot, so a cold-started server, not only a live handoff, restores the pane hibernated and `flk agent resume` brings it back. The agent's profile selector (the `[spawn.env]` keys, such as `CLAUDE_CONFIG_DIR`) is recorded when `agent start` carries it, when the agent's hook first reports its session, and at hibernate, and the resume exports it again, so a resumed Claude agent is logged in to the account it ran under. Agent verbs (`get`, `send`, `hibernate`, `resume` and the rest) resolve an `agent_id` as well as a pane, terminal or name.
- For a restart where a live handoff is not possible: `flk agent hibernate --all` before the stop, then `flk agent list --resumable` and `flk agent resume --all` after the start. Each reports every agent's outcome and exits 1 if any failed. `agent list` marks those agents `"resumable": true`, including agents an unplanned restart left waiting for a deferred resume that a headless server never starts.
- A delegate survives a server restart (#975). Its registry entry records the agent id, and when the restart re-mints the terminal, `flk delegate status`, `send`, `wait` and `result` accept the agent id and update the entry instead of answering `not a delegate`. Entries written before this change are updated the next time a verb confirms the terminal, and a worktree delegate whose agent still runs in its worktree under its name is recognised after a restart.
