- Registered waits (#1031, ADR-0028 §5). `agent.get` and `agent.list` report an agent's oldest open wait as `state.waiting` (`{"on": {wait_id, predicate, since, deadline}}` with the predicate in canonical text, sourced to `wait_registry`), and an idle agent with one open reads `phase: waiting_on_event`. A held `events.read` (`flk events wait`, MCP `flock_events_read` with `wait_ms`) is a wait while it is held, recorded against the agent whose pane runs the caller, so a `flk events wait` started under Claude `run_in_background` reads `waiting_on_event` instead of `finished_with_background`. The new `wait.park` socket method, `flk wait park --until PREDICATE --deadline DUR` and MCP `flock_wait_park` open a wait and return at once, so the agent can end its turn. Predicates: `delegate:<id> phase in [<phases>]` and `reply:<correlation id>`; `pr:<n> ci_completed` and `any-delegate-of-mine changed` are refused with `wait_predicate_unsupported` (exit 2) until #1250, and a delegate on another host with `peer_incompatible`. A park lasts at most 24 h (`wait_deadline_too_long`, exit 2) and an agent holds at most 16 (`too_many_waits`, exit 10). A wait still open at its deadline is announced once as the durable event `wait.expired` and cleared. Protocol 30: against an older server (any protocol below 30, including 29) `flk wait park` exits 78 (`server_version_gap`). Parks end at their deadline until #1032, and do not survive a restart or live handoff yet (#1240).
