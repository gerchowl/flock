- Registered waits (#1031, ADR-0028 §5). `agent.get` and `agent.list` report an agent's oldest open wait as `state.waiting` (`{"on": {wait_id, predicate, since, deadline}}`, sourced to `wait_registry`), and an idle agent with one open reads `phase: waiting_on_event`. A held `events.read` (`flk events wait`, MCP `flock_events_read` with `wait_ms`) is a wait while it is held, recorded against the agent whose pane runs the caller, so a `flk events wait` started under Claude `run_in_background` reads `waiting_on_event` instead of `finished_with_background`. The new `wait.park` socket method, `flk wait park --deadline DUR [--kinds K] [--subject ID]` and MCP `flock_wait_park` open a wait and return at once, so the agent can end its turn. A wait still open at its deadline is announced once as the durable event `wait.expired` and cleared. Protocol 29: against an older server `flk wait park` exits 78 (`server_version_gap`). Parks end at their deadline until #1032, and do not survive a restart or live handoff yet (#1240).
