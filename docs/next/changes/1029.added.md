- `flk events read [--after CURSOR] [--kinds ...] [--subject ID] [--limit N] [--json]` and `flk events wait --kinds ... --subject ID [--after CURSOR] --timeout DUR`, plus MCP `flock_events_read`, the client side of `events.read` (ADR-0028 §5). `events wait` prints the first matching durable event and its cursor (`seq`) and exits 0, or exits 124 at the timeout; the wait is held on the server rather than polled, and without `--after` it waits from the log's current head. `flock_events_read` caps `wait_ms` at 9 minutes, below the MCP tool timeout. Against a server without `events.read` the verbs exit 78 (#1029)
