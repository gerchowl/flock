- `flk goal arm|status|pause|resume|stop` and the socket methods `goal.arm`, `goal.status`, `goal.pause`, `goal.resume` and `goal.stop` (#1155, ADR-0030 §1), the second slice of goal supervision. They change and read the per-agent goal record: arm a goal with its frozen checks, pause it for `--minutes` or until resumed (recorded as `goal_paused` and `goal_resumed`), and stop it. `--agent` defaults to `self`, the agent whose pane runs the command. An agent may arm its own goal but not pause, resume or stop it; the operator and the agent's supervisor (the architect on its delegation edge, matched by agent id, so across restarts too) may do all four. Anyone else, or a caller the server cannot attest, is refused with `goal_caller_refused`, exit 13 like `operator_only` (owner decision 2026-10-13, an ADR-0030 amendment). The check reads process ancestry, so until uid attestation (#1208) an agent's `setsid` child passes as the operator. A timed pause that has run out no longer shows as paused. New error codes `goal_not_armed`, `goal_already_armed` and `goal_not_paused` exit 1; `goal_caller_refused` exits 13. Protocol 30: the four writes exit 78 against an older server before anything is sent, and `goal status` exits 78 through the version-gap diagnosis. Nothing acts on a goal yet: the stop ladder comes in #1157, the MCP tools in #1156.
