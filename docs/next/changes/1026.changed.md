- The agent skill (`SKILL.md`) and the CLI reference stop recommending `pane send-keys … Enter`, or `pane send-text` followed by Enter, to submit a prompt to an agent (#1026). They show `flk agent send <target> "<msg>"`, which submits on its own, and how to read its result: exit 0 the turn started; exit 8 `unconfirmed`, where reason `typed_not_submitted` means the text is still in the composer, so read the pane before sending again; exit 9 `abandoned`, nothing submitted; and a refusal before anything was typed (`not_settled`, `input_not_empty`, …), which exits 10 (#1025). The skill's settled-wait example no longer presses a second Enter after `agent send`. `pane send-keys` stays documented for real key input: dialog answers, `Esc`, arrows.
- Inbox wakes run the same guarded submit as `agent send`, so they share its paste-chip check (#995): a wake the harness folds into `[Pasted text #N]` or `[Pasted Content …]` still gets its Enter and one retry, and a chip left in the composer after both is reported as `unconfirmed` with reason `typed_not_submitted`, as for `agent send`, rather than refused before the Enter.
