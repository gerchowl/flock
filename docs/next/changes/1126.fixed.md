- Panes started in a new background workspace (`flk agent start --no-focus`, `flk delegate start --worktree`) are no longer born a few columns wide (#1126). A new pane copied the size of the first pane on screen, so with the visible workspace split three ways it started about 14 columns wide, and a server with no client attached never laid that workspace out again. New panes now start at the size of a lone pane in the last laid-out window, and a client still resizes them when it shows them. A guarded submit into a pane too narrow for the message also works again (#1122): when the composer shows only the wrapped tail of the sent text, that tail counts as the sent text and gets the Enter and its one retry, as a paste chip does, instead of `owned_composer_not_visible`.
