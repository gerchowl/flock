- `flk server live-handoff` now hands off to the binary of the `flk` you ran, resolved through symlinks, instead of re-executing the running server's own binary. On a versioned install (Nix), the old server's store path stays valid after an upgrade, so a handoff used to restart the old version and still print `live handoff complete`. The CLI now pins the importer to its own version and protocol, waits for the new server to report the target version, and prints both versions (`live handoff complete: server flk A -> flk B`). A client older than the running server refuses the default handoff rather than downgrading it, and a relative `--import-exe` is resolved against the client's current directory. It exits 1 when the replacement is not the requested version, or when an `--import-exe` binary is the version the server already runs while the client is a different version. The `Flock was updated` message now names `flk server live-handoff`, and the explicit `--import-exe "$(readlink -f "$(command -v flk)")"` form for the first upgrade from a client older than this fix, before the stop-and-restart fallback that exits pane processes (#958)
