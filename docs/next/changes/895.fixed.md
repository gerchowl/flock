- A forwarded message whose recipient is gone now reports `recipient_gone` to a multi-hop origin even when the owner first routes it after outcome retention ends. Before, the owner sent `outcome_retention_elapsed`, which an origin still holding the message as `transferred` dropped, so its `msg.status` stayed `custody` until the custody deadline expired it. The owner no longer follows `recipient_gone` with a redundant retention receipt, and each routed-receipt pass now skips settled rows through an index instead of rescanning every multi-hop row in the store.
